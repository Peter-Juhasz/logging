# File logger

A high performance file logger for [`Microsoft.Extensions.Logging`](https://learn.microsoft.com/dotnet/core/extensions/logging), purpose built for a single job: writing every log of an application instance into one file, as fast as possible, without ever losing an entry.

- **One file per application instance**, named after the start time (UTC) and the identifier of the process, like `20261125T101240Z_12345.log`.
- **Never blocks the caller**: no locks, no events, no I/O, no `async` on the logging path. Entries are handed over through a lock-free queue, and written in batches on a dedicated thread.
- **No logs lost**: all pending entries are written when the provider is disposed, when the process exits, and when it crashes because of an unhandled exception.
- **No configuration**: no options, no layouts, no rolling, no filters of its own, so there is nothing to evaluate on every call.
- **AOT compatible** and trimmable.

## Usage

```cs
builder.Logging.AddFile();
```

The log file is written to the `logs` directory next to the application, or to another directory:

```cs
builder.Logging.AddFile("/var/log/my-app");
```

Or to a file with a fixed name, which is appended to across runs, instead of a new file per instance:

```cs
builder.Logging.AddFile("/var/log/my-app", "my-app.log");
```

The file is locked for writing, so only one instance of the application can use it at a time.

Filter levels and categories with the [standard logging configuration](https://learn.microsoft.com/dotnet/core/extensions/logging#configure-logging), using the `File` alias:

```json
{
	"Logging": {
		"File": {
			"LogLevel": {
				"Default": "Information"
			}
		}
	}
}
```

Or without a host:

```cs
using var provider = new FileLoggerProvider();
var logger = provider.CreateLogger("MyApp");
```

## Format

Each entry is a line with the timestamp in UTC, the level, the category, the event identifier (if not zero), and the message, followed by the exception, if any:

```
2026-11-25T10:12:40.1234567Z [INF] MyApp.OrderService[42]: Processed order 12345 for Contoso in 12.5 ms
2026-11-25T10:12:40.1301472Z [ERR] MyApp.OrderService: Failed to process order 12346
System.InvalidOperationException: The order is not valid.
   at MyApp.OrderService.Process(Order order)
```

The file is encoded in UTF-8 without a byte order mark, and lines end with `\n` on every platform. It can be read while the application writes it, by opening it with `FileShare.ReadWrite`.

## How it works

- The logging thread formats the message, captures the time, and appends the entry to a lock-free queue. Scopes are not supported, as capturing them would slow down every call.
- A dedicated background thread polls the queue every 100 ms, so the logging threads do not have to signal it. It encodes the entries to UTF-8 into a 64 KB buffer, and writes it to the file with a single system call, so entries reach the operating system within 100 ms, and survive a crash of the process.
- The queue is unbounded: if the disk cannot keep up with a burst, entries are kept in memory instead of being dropped, or blocking the application.
- When the process exits or crashes, the pending entries are written, and the logger turns synchronous, as the process may terminate any moment: the logs of the shutdown, and of other handlers of the same events, are written before the call returns.
- On disposal, the pending entries are written, and the file is flushed to the disk.

## Performance

The cost of a call on the logging thread, measured by [`LogBenchmarks`](benchmarks/PeterJuhasz.Logging.File.Benchmarks/LogBenchmarks.cs) with messages generated by [`LoggerMessage`](https://learn.microsoft.com/dotnet/core/extensions/logger-message-generator):

| Method        | Mean        | Allocated |
|-------------- |------------:|----------:|
| Constant      |    26.76 ns |         - |
| Arguments     |   135.01 ns |     112 B |
| WithException | 2,270.74 ns |    3208 B |

Most of the time of the calls with arguments and exceptions are spent formatting the message and the exception, which `Microsoft.Extensions.Logging` does.

Logging 100 000 entries from 1 or 4 threads, until all of them are written to the file, compared to Serilog and NLog writing asynchronously without losing entries, measured by [`ComparisonBenchmarks`](benchmarks/PeterJuhasz.Logging.File.Benchmarks/ComparisonBenchmarks.cs) (time per entry):

| Method      | Threads | Mean     | Allocated |
|------------ |-------- |---------:|----------:|
| PeterJuhasz | 1       | 254.8 ns |     197 B |
| Serilog     | 1       | 746.6 ns |     779 B |
| NLog        | 1       | 229.3 ns |     597 B |
| PeterJuhasz | 4       | 250.7 ns |     197 B |
| Serilog     | 4       | 930.3 ns |     790 B |
| NLog        | 4       | 371.1 ns |     680 B |

Run the benchmarks with:

```
dotnet run -c Release --project benchmarks/PeterJuhasz.Logging.File.Benchmarks -- --filter '*'
```
